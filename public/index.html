Encrypted .env archives you can commit

Bundle your environment files into one AES-256-GCM archive, commit it alongside your code, and let teammates restore it with a shared password. A CLI and a terminal UI over the same commands.

Developed with AI assistance, and not formally security audited. Assess it yourself before using it with sensitive data. 

$ goingenv status

Environment Files (3)
  .env
  .env.local
  .env.production

$ goingenv pack

[>] Packing 3 files...
[+] Created .goingenv/archive-20260910-124213.enc

>_Install

Linux and macOS, x86_64 and ARM64. On Windows, use WSL. 

curl -sSL https://raw.githubusercontent.com/spencerjireh/goingenv/main/install.sh | bash

The script verifies the download against the release checksums and refuses to install if they do not match.

A specific version

Replace <tag> with one from the releases page. 

curl -sSL https://raw.githubusercontent.com/spencerjireh/goingenv/main/install.sh | bash -s -- --version <tag>

Other options

  • Manual: download a binary from releases, extract it, and move it onto your PATH.
  • From source: needs Go 1.26 or newer, then go build ./cmd/goingenv.
  • Re-running the installer upgrades in place. Add --cleanup-all to remove old backups and duplicate installations.

>_Usage

Four commands cover the whole workflow.

01Set up .goingenv/ in your project.

goingenv init

02See which files would be packed, before packing them.

goingenv status

03Encrypt them into .goingenv/archive-<timestamp>.enc. You are prompted for a password.

goingenv pack

04On another machine, restore it with the shared password.

goingenv unpack -f .goingenv/archive-20260910-124213.enc

Commit the .enc file. Share the password through a channel that is not the repository — it is never stored.

Every command

CommandDescription
goingenvLaunch the terminal UI
goingenv initSet up .goingenv/ in the current project
goingenv statusShow detected files and existing archives
goingenv packEncrypt env files into an archive
goingenv unpackDecrypt an archive and restore files
goingenv listShow an archive's contents without extracting

Run goingenv with no arguments for the terminal UI, which covers the same operations.

>_Scripting

Every command takes --format. In json and porcelain, stdout carries only the payload and all human output moves to stderr, so the result pipes cleanly. 

goingenv status --format json | jq -r '.env_files[].path'
goingenv status --format porcelain | awk -F'\t' '$1 == "env" { print $2 }'
FormatOutput
textThe default. Human-readable, and not stable — do not parse it
jsonOne JSON object on stdout. Field names are a contract
porcelainTab-separated records, no header row, stable column order
csvlist only

For CI, pass the password by environment variable rather than prompting: goingenv pack --password-env GOINGENV_PASSWORD. Errors go to stderr, as a JSON object under --format json, and the exit code remains the primary signal.

>_Configuration

Settings are read from the first of these that exists.

LocationPurpose
.goingenv/config.jsonProject-local. Commit it to pin how this repository is scanned
~/.goingenv.jsonYour personal default, for projects that do not pin one
built-in defaultsUsed when neither file exists

The first file found wins outright — the two are never merged — so checking out a repository determines its file set regardless of personal configuration. Keys omitted from a file fall back to the built-in default. goingenv init --project-config writes one for you.

Which files get picked up

Patterns are regular expressions matched against the base filename, not globs, and they are unanchored. The default is a single pattern, \.env.*, so anything containing .env matches — including .env.backup, .env.example and myapp.environment. Scanning is depth-limited, 10 directories by default. 

goingenv pack --env-exclude '\.example$'

--exclude is a different thing: it matches directory paths, so it can skip a whole tree but never an individual file.

Config file

{
  "default_depth": 10,
  "env_patterns": ["\\.env.*"],
  "env_exclude_patterns": ["\\.env\\.example$"],
  "exclude_patterns": ["node_modules/", "\\.git/"],
  "max_file_size": 10485760
}
  • default_depth — how many directories deep to scan, 1 to 50
  • env_patterns — filename regexes to include
  • env_exclude_patterns — filename regexes to drop again
  • exclude_patterns — directory paths to skip entirely
  • max_file_size — bytes; larger files are ignored

goingenv status --verbose prints the configuration actually in force, including which file it came from.
